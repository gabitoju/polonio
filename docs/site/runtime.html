HTTP & Runtime

Current CGI and local-development behavior.

CGI mode

With no CLI arguments, Polonio enters CGI mode when GATEWAY_INTERFACE is set. It resolves the template from SCRIPT_FILENAME, falling back to PATH_TRANSLATED, reads CGI environment variables, and reads exactly CONTENT_LENGTH bytes from stdin when supplied. It installs _GET, _POST, _FILES, _COOKIE, and _SERVER, then writes CGI headers followed by the rendered body. CGI errors are emitted as a plain-text 500 response.

Development server

polonio serve [--root DIR] [--port N]

The defaults are the current directory and port 8080. The listener binds only 127.0.0.1. It serves ordinary files with a selected MIME type and renders .pol files. / and directory paths try index.pol, then index.html; extensionless paths try a matching .pol. A root-local 404.pol is rendered for a missing target. Paths escaping the configured root are rejected.

GET and POST are supported. Form, multipart, session, upload, and response helpers use the same runtime wiring as CGI.

Request processing

Query strings populate _GET. POST bodies with application/x-www-form-urlencoded populate _POST; multipart form fields and files populate _POST and _FILES. JSON is retained as the request body and parsed only by request_json(). Use request_body(), request_header(), request_headers(), and cookies() for direct access.

Sessions and security

Set POLONIO_SESSION_SECRET to use session APIs. Session data is JSON encoded and HMAC-SHA256 signed in the polonio_session cookie; invalid signatures are not loaded. The emitted cookie has Path=/; HttpOnly. csrf_token() and csrf_verify(token) are session-backed. Password helpers hash and verify passwords; random_token() uses the runtime secure random source.

Response control

status/http_status, header/http_header, http_content_type, and redirect control the response before headers are emitted. Header names/values reject newline injection. send_file(path) finalizes the response as a file response; no further template body is used for that response.

Storage and uploads

POLONIO_STORAGE_PATH is the sandbox root for storage, SQLite, temporary uploads, downloads, and mail. Server mode defaults it to the served root when unset. Multipart temporary files are created below tmp/uploads; inspect metadata in _FILES and move a file with upload_save(file, path). Use only relative storage paths.

Mail

send_mail(to, subject, body[, headers]) validates its inputs and writes an RFC-like .eml file below outbox in the storage root. SMTP is not implemented.

Server limitations

This is a single-threaded, sequential, loopback-only development server. It has no TLS, keep-alive, streaming, or chunked request-body support. It accepts HTTP/1.1 GET/POST, limits request headers to 64 KiB and bodies to 8 MiB, and closes each connection. Do not use it as a public production server.
