Runnable examples

Small routes arranged from a first template to optional web and data features.

Run the examples

make
export POLONIO_STORAGE_PATH="$PWD/.polonio-storage"
export POLONIO_SESSION_SECRET="development-secret-change-me"
mkdir -p "$POLONIO_STORAGE_PATH"
./build/polonio serve --root ./examples --port 8080

Open http://127.0.0.1:8080/. The root page links to the browser-friendly examples; direct routes also work without the .pol suffix. Storage examples need the environment shown above.

1. Start with templates

Read these first to see the basic template model.

  • hello.pol — variables, interpolation, a loop, and inline output.
  • 404.pol — a custom missing-page template.
  • recovery.pol — recover safely when the optional web-response capability is unavailable.
  • assets/style.css — the small shared stylesheet.

After hello.pol, continue to the Language guide for the concepts used in it.

2. Add web features

These routes need the Web Runtime supplied by the Reference Distribution.

  • forms.pol — query parameters, URL-encoded POST, CSRF, and escaped output.
  • json.pol — parse a JSON request body with request_json().
  • session.pol — a signed session counter.
  • upload.pol — multipart input and upload_save.
  • download.pol — send a stored file; create downloads/example.txt first.
  • mail.pol — write a message to the local outbox, not an SMTP server.

3. Store data

These routes use the Data Runtime and the configured storage root.

  • storage.pol — sandboxed directories and files.
  • sqlite.pol — create a table, insert safely, query, and close SQLite.

Use canonical function names such as html_escape and to_string. Look up signatures in Built-in functions, then read Runtime for contexts and local-server limits.
